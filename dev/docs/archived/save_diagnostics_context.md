# Save Diagnostics Context: Pull → Push (Compact Implementation Note)

Bounded refactor — no behavioral change to what the player sees, only how diagnostics are collected. Coordinates below are as-found at time of writing.

## Goal

Replace the per-store pull-model diagnostics plumbing (`_migration_log` + `_restore_warnings` accumulator fields, their return-and-clear getters, and per-manager aggregation) with a single `SaveLoadContext` object threaded through the load path. `SaveManager` creates one context per load, every `from_dict` writes into it, and `SaveManager` drains it once at the end. This collapses two parallel accumulator systems plus their reflective drain into one push channel, and removes the optional collector array on `ItemEntry.from_dict()` — the last silent-swallow path. The trigger was `StorageStore.from_dict()` allocating a per-entry `issues` array only to read `is_empty()`; the array's contents were never used.

## Context (as found)

- Current model is **pull**: `StoreBase` (`common/gameplay/store/store_base.gd`) holds `_migration_log` (L11) and `_restore_warnings` (L16) with return-and-clear getters `get_migration_log()` (L21) and `get_restore_warnings()` (L29). Each store's `from_dict()` / `_apply_migrations()` appends to these.
- Managers re-aggregate per store: `MetaManager` (`global/autoloads/managers/meta_manager.gd`) `get_migration_log()` (L58-66) and `get_restore_warnings()` (L71-79) each loop its six stores; `KnowledgeManager` (`global/autoloads/managers/knowledge_manager.gd`) mirrors with single-store passthroughs (L92-93, L98-99).
- `SaveManager` (`global/autoloads/save_manager.gd`) dispatches `provider.from_dict(sections_data)` (L170) then calls `_collect_migration_logs()` (L171, def L357-368), which reflectively probes each provider with `has_method("get_migration_log")` / `has_method("get_restore_warnings")` and routes messages to `ToastManager.show_info` (debug-only) and `ToastManager.show_warning` (always visible) respectively.
- The waste site: `StorageStore.from_dict()` (`common/gameplay/store/storage_store.gd` L72) builds `var per_issues: Array = []` per entry (L88), passes it to `ItemEntry.from_dict(d, per_issues)` (L89), and reads only `not per_issues.is_empty()` (L93) to bump `degraded_count`. The string payload is discarded; the per-entry detail only ever reaches the debug console via `push_warning` inside `ItemEntry.from_dict()`.
- `ItemEntry.from_dict(d, issues: Array = [])` (`common/gameplay/instance/item_entry.gd` L512) pairs `issues.append(x)` with `push_warning(x)` at three sites (anchor miss L520-521, surface clue miss L528-529, hidden clue miss L535-536). The `= []` default means a caller that omits the array silently loses every issue.
- Severity routing today: data-loss summary → `show_warning` (player-visible); per-entry/clue detail and schema-migration notes → `show_info` (debug-only) + `push_warning` console. This split must be preserved.

## Implementation Notes

- **Severity mapping is the load-bearing decision.** `ctx.warn` → `show_warning` (always visible) carries only the player-facing data-loss summary (the `StorageStore` "N dropped, M degraded" line). `ctx.info` → `show_info` (debug-only) carries every per-entry/clue detail and every schema-migration note. Routing a per-clue detail to `warn` would spam the release toast — keep details on `info`.
- **Degraded derivation, no signal needed.** After `var entry := ItemEntry.from_dict(d, ctx)`, drop on `entry == null`; otherwise compare `d.get("surface_ids", []).size() + d.get("hidden_ids", []).size()` (listed) against `entry.surface_clues.size() + entry.hidden_clues.size()` (resolved). An unresolved clue id is never appended, so `resolved < listed` is exactly "degraded". This removes the need for any collector array or result struct purely to derive the count.
- **Context lifetime.** One `SaveLoadContext` per `load()`, constructed inside the candidate loop just before provider dispatch — not before the loop — so a candidate file that fails validation and falls through to the next does not leave stale messages in the context. The context is drained once, right after the successful provider dispatch.
- **Required, never optional.** `ctx` takes no default value anywhere. The whole point of the refactor is to eliminate the `issues: Array = []` optional path where a forgetful caller silently swallows diagnostics; a defaulted `ctx` would reintroduce it.
- **`_apply_migrations` ripple.** Only `StorageStore` overrides `_apply_migrations`; its `from_dict` must forward `ctx` into the call. The `StoreBase` default no-op override gains the param for signature parity.
- **`register_provider` is unaffected** — its assertions (`save_manager.gd` L50-52) probe `has_method("from_dict")` by name only, independent of arity.
- **Comment preservation** (project rule): update only the docstrings whose described behavior changes (the migration-log example in `store_base.gd`, the `StorageStore.from_dict` summary docstring); do not strip surrounding comments.
- **Out of scope:** `CustomerEntry`/`CustomersStore` restore detail hardening — `CustomersStore` only gets the signature update here; deeper per-entry diagnostics can adopt the same `ctx` later. No change to save-file format, schema version, or `to_dict()`.

## Edge Cases

| Case                                            | Expected Handling                                                                            |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Clean load (no loss, no migration)              | `ctx.warnings` and `ctx.infos` both empty → no toast, identical to today                     |
| Release load, anchor unresolvable               | `ItemEntry.from_dict` returns null → dropped count → one `ctx.warn` summary → `show_warning` |
| Release load, some clue ids unresolvable        | Entry kept, degraded by structural count → counted into the same summary `ctx.warn`          |
| Per-entry / per-clue detail                     | `ctx.info` → `show_info` (debug-only) + `push_warning` console — unchanged from today        |
| v1 save schema migration notes                  | `ctx.info` → `show_info` (debug-only) — same visibility as the old `_migration_log` path     |
| Candidate file fails validation, next one loads | Fresh `ctx` per successful dispatch → no stale messages bleed from the rejected file         |

## Acceptance Criteria

1. A release-build load that drops or degrades any storage item shows the same player-visible warning toast (with counts) as before; a clean load shows nothing — the player-facing behavior is preserved through the new channel.
2. Schema-migration messages still surface as debug-only info toasts; no migration note leaks into the always-visible warning channel.
3. No store or manager retains a `_migration_log` / `_restore_warnings` field or a `get_migration_log()` / `get_restore_warnings()` method; all diagnostics flow through the threaded `SaveLoadContext`.
4. `ItemEntry.from_dict()` takes no issues/collector array; degraded detection is derived structurally inside the store from resolved-vs-listed clue counts.
5. Every `from_dict()` and `_apply_migrations()` on the save path takes a non-optional `SaveLoadContext` — no default-argument path remains by which diagnostics can be silently dropped.
6. A headless compile is clean (no arity-mismatch errors), confirming every `from_dict` call site was updated.
