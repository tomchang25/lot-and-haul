# SFX Pipeline: Phase 1 — Generator

## Goal

A Python CLI that reads a YAML synth-patch description in real-world units (Hz, seconds, semitones, dB), renders deterministic 44.1 kHz 16-bit mono WAVs with mechanical QC (peak-normalize to −3 dBFS, 5 ms fade-out, 2 s hard cap), and emits a matching `UiAudioEvent` `.tres` playback resource — so a sound goes from YAML to playable in-game with zero hand-editing of assets or resources.

## Relational Context

- **The SFX renderer is NOT an `EntitySpec` in the existing YAML-to-TRES pipeline.** The existing `yaml_to_tres.py` iterates bulk YAML files per designer data type (items, clues, categories) in dependency order and writes `.tres` files under `data/tres/`. The SFX renderer is a separate single-file CLI that reads one YAML at a time and produces two outputs: a WAV (under `assets/audio/placeholder/`) and a `UiAudioEvent` `.tres` (under `data/tres/audio_events/`). It does not participate in the REGISTRY or depend on other entity types.
- **`UiAudioEvent`** (`common/audio/events/ui_audio_event.gd`) extends `AudioEvent`. Key fields the generated `.tres` must set: `streams` (Array of `AudioStream`, referencing the WAV file(s) via `ExtResource`), `volume_db` (float), `bus_id` (int enum, always `AudioBus.Id.UI` = 2), `use_random_pitch` (bool), `pitch_random_min`/`pitch_random_max` (float), `limiter_key` (StringName), `max_per_window` (int), `window_sec` (float). The base `AudioEvent` defaults are `volume_db = 0.0`, `bus_id = NONE` — so the generator must explicitly set `bus_id = 2` (UI).
- **The Godot WAV import pipeline:** Godot's default importer converts `.wav` files to `AudioStreamWAV` resources automatically. The generated `.tres` references the WAV via `ExtResource` with the WAV's path as `res://assets/audio/placeholder/<name>_v01.wav`. The WAV gets a deterministic UID at import time — but since the UID is generated by Godot (not the CLI), the `.tres` must NOT embed a UID for the `ExtResource`; it uses only the `path` field. Godot resolves `path`-only references on next editor re-import.
- **Determinism constraint:** the renderer uses a per-file `seed` field from the YAML. The same YAML + same seed must produce byte-identical WAV output. Python's `wave` module writes header fields that include the data length — this is naturally deterministic given identical audio data. The synth math (oscillators, envelopes, noise) must use Python's `random.Random(seed)` (or `hashlib`-seeded deterministic RNG) rather than `os.urandom` or `time.time`.
- **Existing generation prompt structure:** `dev/tools/prompts/yaml_generation/` holds `base.md` (shared rules), `category.md`, and `item.md`. The SFX generation prompt follows the same pattern: `sfx.md` at the same level, referencing `base.md` rules for output format (no fences, two-space indent, snake_case IDs) and contributing its own schema definitions and intent→sound conventions.
- **The `DataPaths` constants class** (`global/constants/data_paths.gd`) does not include entries for `assets/audio/placeholder/` or `data/tres/audio_events/` — those are new paths that do not need a DataPaths constant (they are not loaded by any ResourceRegistry autoload). Only `UiAudioEvent` resources need runtime loading, and they are loaded by explicit `preload` or `load` in wiring code, not by a registry.

## Plan Friction

- Settled: No friction found between Plan and codebase. All referenced systems (`UiAudioEvent`, `AudioManager.play_event()`, the `.tres` format, `TresWriter`, `deterministic_uid`) exist as described in the Plan.

## Design Gaps

- Settled: **WAV output directory.** `assets/audio/placeholder/` — the existing `assets/` directory holds static game assets (car sprites, warehouse images); `audio/placeholder/` is a new subdirectory clearly marking these as replaceable. Created by the CLI if absent. A trailing `/.gdignore` is NOT added (Godot must import the WAVs for `AudioStreamWAV` loading to work).
- Settled: **Audio event `.tres` output directory.** `data/tres/audio_events/` — follows the existing convention where `data/tres/` holds all generated `.tres` files by type. Created by the CLI if absent.
- Settled: **YAML source directory.** `data/yaml/sfx/` — follows the convention that `data/yaml/` holds all authored YAML, one subdirectory per concern. The CLI reads a single YAML file path (or a glob directory), not a pre-merged bulk dataset — this is a design divergence from `yaml_to_tres.py` because each sound is independently authored and rendered.
- Settled: **CLI invocation.** `python dev/tools/render_sfx.py --yaml <path> --godot-root <path>` — single-file mode. With `--dir <path>`, process all `*.yaml` files in a directory. `--dry-run` prints what would be generated. `--force` re-renders existing WAVs (otherwise skips if WAV exists and seed matches). No `--yaml-dir` default — the path is required.
- Settled: **No Python audio dependencies.** The synth uses the `wave` module (stdlib) for WAV I/O, `math` for oscillators (sin, pi), and a pure-Python noise generator. No PyAudio, numpy, or scipy. This keeps the project's tool dependency to only `pyyaml` (already required) and `pillow` (already required for background generation).
- Settled: **Generation prompt location.** `dev/tools/prompts/yaml_generation/sfx.md` — consistent with `item.md` and `category.md` at the same level. The legacy entrypoint `dev/tools/prompts/yaml_generation_prompt.md` gets a pointer added referencing `sfx.md`.
- Settled: **Variant naming.** A sound with `variant_count: 1` produces `<name>.wav` (no suffix). With `variant_count: 3`, produces `<name>_v01.wav`, `<name>_v02.wav`, `<name>_v03.wav`. The `.tres` has `streams = [ExtResource(v01), ExtResource(v02), ExtResource(v03)]`. The base WAV (no suffix) is not produced when variants > 1 — the variants ARE the streams.
- Settled: **Seed perturbation for variants.** Variant 0 uses `seed` from YAML directly. Variant N uses `seed + N` (simple additive offset). The re-run check: if the WAV exists and its embedded seed metadata (convention: first 4 bytes of the `cue` chunk, big-endian integer) matches the expected seed, skip re-rendering. This makes `--force` unnecessary for normal iteration — only changed fields cause re-render.
- Settled: **The `.tres` ExtResource for WAVs uses path-only references (no UID).** Godot assigns UIDs to imported assets at import time; the CLI cannot predict them. The `path` field alone (`res://assets/audio/placeholder/<name>_v01.wav`) is sufficient for Godot to resolve the reference after editor import or at runtime via `load()`.

## Scope

### Included

- `render_sfx.py` CLI: YAML → WAV + `.tres` rendering, with deterministic seed, QC pass, variant support, and idempotent re-run.
- Pure-Python synth engine module (`sfx_synth.py`): oscillator bank (sine, square, saw, triangle, noise), envelope generator (ADSR with sustain punch), pitch slide/sweep, vibrato LFO, arpeggio sequencer, resonant low-pass/high-pass filters (simple 1-pole), bitcrush effect.
- `UiAudioEvent` `.tres` generation from the YAML's `playback` section.
- `data/yaml/sfx/` directory creation (empty, ready for Phase 2).
- `assets/audio/placeholder/` directory creation and `.gitignore` entry for generated WAVs.
- `dev/tools/prompts/yaml_generation/sfx.md` with full schema, real-unit field definitions, default tables, and intent→sound conventions.
- Update to `dev/tools/prompts/yaml_generation_prompt.md` to add a pointer to `sfx.md`.

### Excluded

- No quality loop, iterative refinement, or similarity scoring.
- No music generation or positional/2D audio.
- No runtime synthesis in Godot — all sounds are pre-rendered offline.
- No `EntitySpec` integration in the existing `yaml_to_tres.py` REGISTRY.
- No changes to `AudioManager` or any existing Godot script — the generator produces files the engine consumes.

## Implementation Notes

### `sfx_synth.py` — Synth Engine

```
Sampling: 44100 Hz, 16-bit signed mono
Output: list of int16 samples (frame buffer)
```

Waveform generators (all return `float` in [-1.0, 1.0] at a given phase `t` in [0.0, 1.0)):
- `sine(t)` → `sin(2π * t)`
- `square(t, duty)` → `1.0 if t < duty else -1.0` (default duty 0.5)
- `saw(t)` → `2.0 * t - 1.0`
- `triangle(t)` → `4.0 * abs(t - 0.5) - 1.0`
- `noise()` → `random.uniform(-1.0, 1.0)` (deterministic via `rng.random()`)

Envelope: ADSR with sustain punch. Parameter units in seconds (attack/decay/release) and amplitude factor (sustain, punch):
- Attack: linear ramp 0 → 1.0 over `attack` seconds
- Decay: linear ramp 1.0 → `sustain_level` over `decay` seconds
- Sustain: hold at `sustain_level` for `sustain` seconds. If `punch > 0`, the sustain level briefly spikes to `sustain_level * (1.0 + punch)` at the start of the sustain phase and decays back over 0.02 s.
- Release: linear ramp `sustain_level` → 0 over `release` seconds

Pitch slide: maps to frequency multiplier over the note duration.
- Start: `pitch_start_hz`
- End: `pitch_end_hz`
- Curve: linear interpolation from start to end. If `slide_curve` is provided, apply power curve (`t^curve` for positive, `1 - (1-t)^(-curve)` for negative) to shape the interpolation path.

Vibrato: sinusoidal LFO modulating pitch.
- Depth in semitones → frequency multiplier = `2^(depth/12)`
- Rate in Hz
- Applied on top of the pitch slide.

Arpeggio: instantaneous pitch shifts at regular intervals.
- `shifts`: array of semitone offsets
- `step_time`: seconds between shifts
- Cycle through shifts repeatedly; applied on top of pitch slide + vibrato.

Filter: simple 1-pole IIR low-pass and high-pass.
- Low-pass: `y[n] = a * x[n] + (1-a) * y[n-1]` where `a = 2π * cutoff / sample_rate` (clamped to [0, 1])
- High-pass: `y[n] = a * (y[n-1] + x[n] - x[n-1])` where `a = 1 / (1 + sample_rate / (2π * cutoff))`
- Bitcrush: reduce bit depth (quantize to N levels) and/or sample rate reduction (hold each sample for K frames).

Rendering loop:
```
for each frame in [0, num_frames):
    t = frame / sample_rate
    freq = pitch_at(t)  # Hz, after slide + vibrato + arpeggio
    phase_delta = freq / sample_rate
    phase = (phase + phase_delta) % 1.0
    sample = oscillator(phase)  # [-1.0, 1.0]
    sample = filter(sample)
    sample *= envelope(t)  # ADSR
    sample = min(max(sample, -1.0), 1.0)
    samples.append(int16(sample * 32767))
```

QC post-process:
1. Find peak amplitude across all samples
2. If peak > 0, scale all samples so that peak = `10^(-3/20)` = ~0.7079 (−3 dBFS)
3. Apply 5 ms linear fade-out at the tail (multiply last N frames by 0→1 ramp)
4. Trim to 2 s max (88200 frames). If the envelope would produce sound beyond 2 s, the release is truncated.
5. Write via `wave.open(path, 'w')` with `nchannels=1, sampwidth=2, framerate=44100, comptype='NONE'`

### `render_sfx.py` — CLI

```python
python dev/tools/render_sfx.py --yaml data/yaml/sfx/click.yaml --godot-root /workspace
python dev/tools/render_sfx.py --dir data/yaml/sfx/ --godot-root /workspace
python dev/tools/render_sfx.py --yaml path/to/sound.yaml --godot-root /workspace --dry-run
python dev/tools/render_sfx.py --dir data/yaml/sfx/ --godot-root /workspace --force
```

Processing flow per YAML:
1. `yaml.safe_load()` the file
2. Extract `sound_id` (basename), `seed` (int), `variant_count` (int, default 1)
3. For each variant `v` in `range(variant_count)`:
   a. Compute `variant_seed = seed + v`
   b. Create a `random.Random(variant_seed)` for noise/variation
   c. Call `sfx_synth.render(yaml_params, rng)` → frame buffer
   d. Write WAV to `assets/audio/placeholder/{sound_id}_v{v+1:02d}.wav`
   e. Skip if WAV exists and seed-cue matches (idempotency check)
4. Build `UiAudioEvent` `.tres` using `TresWriter`:
   - `resource_type = "Resource"`, `script_class = "UiAudioEvent"`
   - `uid = deterministic_uid("audio_event", sound_id)`
   - ExtResource for script: `common/audio/events/ui_audio_event.gd` (read `.gd.uid`)
   - ExtResource per WAV variant: path-only (no UID), type `"AudioStreamWAV"`
   - Fields: `streams = [...]`, `volume_db`, `bus_id = 2` (AudioBus.Id.UI), `use_random_pitch`, `pitch_random_min/max`, `limiter_key`, `max_per_window`, `window_sec`
5. Write `.tres` to `data/tres/audio_events/{sound_id}.tres`

The YAML schema the CLI reads (mirrors what the generation prompt defines):

```yaml
sound_id: click
seed: 42
variant_count: 2
source:
  waveform: square       # sine | square | saw | triangle | noise
  duty_cycle: 0.5        # square wave only, 0.0-1.0
pitch:
  start_hz: 800
  end_hz: 400
  slide_curve: 0.0       # 0 = linear, positive = ease-in, negative = ease-out
  vibrato_depth: 0.0     # semitones
  vibrato_rate: 0.0      # Hz
  arpeggio_shifts: []    # list of semitone offsets, empty = no arpeggio
  arpeggio_step_time: 0.0
envelope:
  attack_s: 0.001
  decay_s: 0.02
  sustain_s: 0.05
  release_s: 0.03
  sustain_level: 0.6
  sustain_punch: 0.0
color:
  lp_cutoff_hz: 0        # 0 = no low-pass
  hp_cutoff_hz: 0        # 0 = no high-pass
  bitcrush_bits: 16      # < 16 to reduce; 16 = off
playback:
  bus: UI                 # always UI for this pipeline
  volume_db: -6.0
  pitch_random_min: 0.98
  pitch_random_max: 1.02
  limiter_key: ""
  max_per_window: 8
  window_sec: 0.05
```

### Generation prompt — `sfx.md`

Structure follows `item.md`:
1. Schema section with every field, its type, range, default, and real-unit meaning
2. Defaults table (quick reference)
3. Intent→convention mapping table (confirm = short pitch-up, error = low buzz, reveal-good = bright chime, hit = noise burst with fast decay, click = very short square spike, cash = ascending arpeggio, sale-complete = medium sustained chord-like, auction-won = rising fanfare, auction-lost = descending tone)
4. Validation rules (seed is required integer, variant_count >= 1, length caps, no empty fields)
5. Output format rules (same as `base.md`: no fences, two-space indent, no YAML comments)

### `data/tres/audio_events/` generation

The `.tres` follows the same format as existing generated `.tres` files:

```
[gd_resource type="Resource" script_class="UiAudioEvent" format=3 uid="uid://generateduid"]

[ext_resource type="Script" uid="uid://scriptuid" path="res://common/audio/events/ui_audio_event.gd" id="1_script"]
[ext_resource type="AudioStreamWAV" path="res://assets/audio/placeholder/click_v01.wav" id="2_stream_0"]
[ext_resource type="AudioStreamWAV" path="res://assets/audio/placeholder/click_v02.wav" id="3_stream_1"]

[resource]
script = ExtResource("1_script")
streams = [ExtResource("2_stream_0"), ExtResource("3_stream_1")]
volume_db = -6.0
bus_id = 2
use_random_pitch = true
pitch_random_min = 0.98
pitch_random_max = 1.02
limiter_key = &"click"
max_per_window = 8
window_sec = 0.05
```

The `deterministic_uid()` for the event resource uses `sfx_audio_event` as the entity_type prefix to avoid collisions with any future audio event registry.

## Edge Cases

| Case | Expected Handling |
| --- | --- |
| YAML missing `sound_id` | CLI exits with error: "sound_id is required" |
| `variant_count: 0` | CLI treats as 1 (warns) |
| Zero-length envelope (all phases = 0) | CLI sets a minimum total duration of 0.01 s (441 frames) to prevent empty WAV |
| WAV peak-normalize with silent input (all zeros) | CLI skips normalization (no divide-by-zero); writes silent WAV |
| WAV already exists with matching seed cue | CLI skips (idempotent re-run). The seed is stored in a WAV `cue` chunk (first 4 bytes as big-endian int). WAVs from before this feature (no cue chunk) always re-render |
| `--force` flag | Deletes existing WAV(s) for matching sound_id before rendering; always re-renders |
| Godot imports WAV at 44100 Hz as stereo | Default Godot WAV import preserves mono as mono (`force/format` = 0). No special handling needed |
| `.tres` references WAV that doesn't exist yet | The `.tres` is written after all WAV variants; if a variant render fails, the CLI exits before writing `.tres` |

## Acceptance Criteria

1. Running `python dev/tools/render_sfx.py --yaml <path> --godot-root <path>` on a valid YAML produces a WAV file under `assets/audio/placeholder/` and a `.tres` file under `data/tres/audio_events/`.
2. Re-running the same command produces byte-identical WAV output (verified via `sha256sum`).
3. A YAML with `variant_count: 3` produces three WAVs with distinct audible content and a single `.tres` whose `streams` array contains all three.
4. The generated WAV does not clip (peak ≤ −3 dBFS), has no audible pop at the tail (5 ms fade-out), and is ≤ 2.0 s.
5. The generated `.tres` loads in Godot as a valid `UiAudioEvent`, with the correct `bus_id` (UI), `streams` populated, and playback metadata set.
6. `python dev/tools/render_sfx.py --dry-run --yaml <path> --godot-root <path>` prints what would be written without creating any files.
7. The generation prompt at `dev/tools/prompts/yaml_generation/sfx.md` describes every field with its real unit, range, default, and includes an intent→convention mapping table.
